# 浏览器访问流程

## 执行顺序

1. 发现运行时浏览器导航、快照、输入、点击和诊断能力。工具延迟加载时按名称和描述搜索；可调用后检查当前页签。普通文本读取不能代替动态结果页验收。
2. 浏览器打开正常入口，记录最终URL路径及主文档状态。导航完成后等待检索框或结果行等目标元素；不要仅以DOMContentLoaded或整页网络空闲作为业务就绪证据。
3. 检查免责声明、登录、验证码和弹窗。用户需本人处理的交互保持同一会话；不得复制其他进程Cookie。只有用户能够看到和操作该会话时才让其登录。操作不能继续时记录 interaction_required，继续其他数据库。
4. 执行一条最小检索，记录实际查询、集合、结果数、第一页首条公开号及生效证据。零命中必须确认是本次提交后的结果而非旧页面。
5. 按 coverage.md 执行计划批次，读取详情、摘要及独立权利要求。对搜索页和详情页分别诊断。
6. 原始笔记与安全诊断留在任务工作区；按 report.md 披露未覆盖部分。

## 中国专利公布公告站

从 sources.md 的高级查询入口进入，按照 [epub.md](epub.md) 填写著录字段及类型并提交。先确认实际结果页的名称、首条公开号、总页数，再逐页核对；0 条只在本次查询已返回结果时成立。详情页可核对著录信息与摘要；若不能阅读独立权利要求，标记“仅摘要初筛”。遇到挑战页、验证码或 HTTP 错误时记录具体阶段，不把页面空白当成零结果。

## Google Patents

在正常搜索界面输入产品词“four-way pallet shuttle”并检查结果；另测试一件已知号码的公开文献页。503等异常按 diagnostics.md 处理，两类页面分别记录。若搜索页只有外壳，检查浏览器渲染及目标元素；若详情页可用，仍不能宣称结果列表已经覆盖。用正常UI调整关键词、申请人和日期字段，保留站点最终显示的查询语义。

## PATENTSCOPE

进入 sources.md 的入口并等待简单检索框，允许站点正常重定向到其官方域名。记录当前界面实际选择的PCT或其他国家集合；集合未知时填 null，不能推断为PCT。

先执行产品词检索，例如 `"four-way" AND shuttle`，在结果页确认查询和命中数，提取首条公开号。搜索框与按钮以实时快照或DOM定位；带冒号的元素ID可用 `[id="完整ID"]`，不长期固定自动生成按钮ID。提交后等待结果容器更新。要求机器人验证时停止此通道，由用户手动处理；不要调用内部XHR绕过验证。

## 缺少浏览器工具

公布公告站优先运行本技能自带的 scripts/epub_search.py；若新建浏览器会话最终拒绝而已有用户可见会话可用，可按 epub.md 用本机 CDP 连接或使用可控制浏览器正常检索并记录结果。脚本会等待初始 HTTP 202 后的最终业务页面；若变成 HTTP 400，不以登录或反爬作未经证实的归因。Google Patents和PATENTSCOPE目前没有本地批量适配器；无可用浏览器时列明缺口，不能把搜索摘要补报成数据库结果。不要在首次失败后盲目安装依赖或变换代理。
