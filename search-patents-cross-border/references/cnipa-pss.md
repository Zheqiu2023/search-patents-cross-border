# 国家知识产权局专利检索及分析系统操作流程

入口：`https://pss-system.cponline.cnipa.gov.cn/conventionalSearch`。

该系统是默认的中国官方检索来源。登录状态、可检索字段和结果页布局可能调整，每次任务都以当次页面为准。登录由用户在可见浏览器中完成；登录后的检索、结果读取和覆盖记录由智能体完成。

## 1. 打开与登录边界

1. 用正常浏览器打开上述入口，等待页面标题出现“常规检索”，不要只等待导航完成。
2. 检查右上角状态：显示用户姓名表示已登录；显示“登录”表示尚未登录。
3. 未登录时，把当前可见窗口交给用户完成账号、密码、短信或验证码操作。不要代填凭据、不要读取或保存 Cookie，也不要请求用户把密码发到对话中。
4. 用户确认登录后，再读取页面确认用户姓名已出现、登录入口消失，然后开始检索。
5. 若页面提示“业务访问触发安全防护规则，请刷新页面后访问业务”或变为空白，先关闭页面并重新打开入口，等待 10 至 30 秒再试；不要连续点击登录或提交。该提示属于访问状态，不是零命中。

## 2. 选择检索字段

默认模式是“自动识别”。输入框上方还有“检索要素、申请号、公开号、申请人、发明人、发明名称”等模式。

- 点击目标模式后，确认输入框占位文字和“检索模式：……”同步改变，再输入检索词。
- 名称检索用于控制召回范围；摘要和全文检索容易把仅提及目标词的文献带入，应单独记录字段。
- 2026-11-16 的“自动识别”页面提示：空格分隔的多个检索词默认按 AND 处理，支持显式 `and`、`or` 和半角括号；每次以当前字段的页面提示为准。输入中含空格、保留关键字或运算符时，按页面提示使用半角双引号。但该系统仍可能对中文进行分词，**不要假定加引号后结果就是严格短语匹配**。用结果总数、首条名称和抽查摘要确认实际召回。
- 多组检索词应分别记录，不要因为页面结果数较大就直接相加；不同字段和分词方式的结果会重叠。

## 3. 提交检索并识别真正的按钮

页面顶部导航和输入框右侧都显示“检索”，这是本系统最容易误操作的定位点。

必须点击输入框右侧、带搜索图标且位于 `div.btn` 内的检索按钮。使用文本选择器时可能命中顶部导航，造成空白结果页或 HTTP 400。浏览器自动化优先使用：

```js
page.locator('div.btn').filter({ hasText: '检索' }).click();
```

不要使用只按文字“检索”定位的通用选择器，也不要在点击后立刻读取页面。

点击后有两种正常情况：

- 新建结果标签页，URL 以 `/retrieveList?prevPageTit=changgui` 开头；首次提交常见此行为。
- 已有结果页被复用或更新，URL 仍是 `/retrieveList`；修改检索词后常见此行为。

自动化应同时处理两种情况：若出现 popup，等待 popup 的主文档和结果数量；若没有 popup，则等待已有 `/retrieveList` 页面更新。不要因为“没有新标签页”就断定检索没有被提交。

建议等待 4 至 6 秒，直到页面标题为“检索结果”且出现 `N 条数据`，再读取首条记录。若立即读取到空 HTML、空白页或 HTTP 400，记录为“结果页尚未就绪或提交定位错误”，返回常规检索页用正确按钮重试一次；不要把 400 记为零命中。

## 4. 结果页确认

结果页应同时具备以下业务元素：

- 面包屑“常规检索 / 检索结果”；
- 左侧“筛选”区，包括专利类型、有效专利、申请日、公开日、授权日；
- 结果统计文字 `N 条数据` 和分页区 `共 N 条`；
- 公开号、申请号、申请日、发明名称、申请人五列；
- 每条记录的“摘要、主权利要求、著录项目、IPC分类、CPC分类、法律状态、同族、引证、被引证”页签。

记录当次结果显示的总数、第一页首条公开号、排序方式和实际读取页码。若总数与分页区不一致，保留两个数字并标记为待核实。

结果默认每页 10 条，可在分页区选择每页条数或输入页码。翻页后必须确认首条公开号发生变化；同一页重复出现或页号跳变时，将覆盖标记为部分。

## 5. 筛选和详情核验

1. 先用专利类型、有效专利和日期范围收窄候选；筛选条件必须和结果数一起写入检索日志。
2. 在结果行展开“摘要”做标题/摘要初筛；需要核对权利要求时点击“主权利要求”，不要用摘要代替权利要求。
3. 点击公开号或“详览”读取著录项目、申请日、优先权、申请人、发明人和法律状态。
4. 法律状态页签只作为线索；需要正式权属或有效性结论时，继续查对应官方登记记录。
5. 同族页签可用于发现成员，但未核实的同族不得直接合并；A/B 文献和同一申请的不同公开文本要按号码分别记录。

## 6. 批次、覆盖与常见故障

- 每次换检索词、字段、筛选条件或日期范围都建立新的 `batch_id`，并记录完整查询、模式、结果数、首条公开号、总页数和已读页码。
- 结果数较大时按日期、申请人或分类号拆成不重叠批次；拆批后按公开号去重，不能把各批次命中数直接相加当成唯一专利族数。
- 只有已读至最后一页、且末页记录数与页面总数相符，才可写 `coverage_complete: true` 并附 `terminal_evidence: true`；只读了前几页必须写 `partial`。
- 登录页正常但业务页 400、空白或页面提示安全防护时，记录入口、最终 URL、HTTP 状态、页面提示和尝试次数，有限重试后继续 Google Patents、WIPO 等其他来源。
- 不要通过内部 XHR、复制 Cookie、切换代理或绕过验证码来恢复检索；只使用正常页面和用户已授权的会话。

## 7. 已验证的最小流程

2026-11-16 在本机可见浏览器中完成的验证顺序如下：

1. 打开 `conventionalSearch`，由用户完成登录，页面显示用户名。
2. 在“自动识别”输入 `四向车`，点击 `div.btn` 内的检索按钮。
3. 结果页显示“检索结果”和 `467 条数据`，首条公开号可读。
4. 切换“发明名称”后再检索 `四向车`，结果页显示 `305 条数据`，证明字段切换和结果页复用均正常。
5. 使用 `div.btn` 定位并等待结果页加载，能够消除此前因点到顶部导航、过早读取新标签页造成的空白和 HTTP 400。

命中数量是验证时点的数据，不写入固定预期；复测时以页面实际显示为准。
